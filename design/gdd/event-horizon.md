# 事件视界 (Event Horizon)

**类型：** 第一人称驾驶舱操作 / 资源管理生存
**引擎：** Godot 4.6 (GL Compatibility) + Jolt Physics
**美术风格：** Blockbench Low-Poly 驾驶舱 + 程序化小地图 + 像素风仪表盘
**目标时长：** 25-30 分钟
**主题契合：** 视界限 — "有限的视野构建无限的悬念"
**开发周期：** 3 周 / 2 人 / 每人每日 2 小时 (共 84 人时)

---

## 1. Overview

玩家驾驶一艘受损飞船被黑洞引力捕获，通过分散在驾驶舱各处的物理控件（旋钮/按钮/开关/拉杆）手动操控飞船。主监视器显示一张 2D 小地图，玩家在上面实时驾驶飞船，在引力场和碎片之间导航，飞向目的地标记。核心体验是多任务管理：驾驶需要持续注意力，但系统故障（断路器跳闸、氧气报警、引擎过热）不断打断驾驶。地图数据不自动更新，必须手动扫描刷新。正确的逃逸路线不是远离黑洞，而是利用最深的引力弹弓效应——穿越视界限本身。

**核心矛盾：** 驾驶需要持续操作注意力 vs 系统故障不断需要修理 vs 地图数据过时需要刷新。你必须在不充分的信息和持续的系统压力下做出导航决策。

**设计参考：** 《铁肺》的驾驶舱受限信息体验，但去除恐怖元素，转向"坦克/潜艇驾驶"的操作手感和资源管理生存。

---

## 2. Player Fantasy

**核心幻想：** 你坐在一艘快要散架的飞船里，周围是分散的控制台。你必须一边用旋钮和拉杆驾驶飞船穿过引力场，一边不断修复跳闸的断路器和过热的引擎。你能依靠的只有手边的控件、主屏幕上的小地图，和不完整的直觉。

**情感曲线：**

```
节点0: 迷茫 → "这些控件都是干什么的？"的学习感
节点1: 紧张 → 开始理解驾驶，首次面对选择
节点2: 沉重 → 在碎片中穿行，发现前人失败的证据
节点3: 焦虑 → 信息最不充分，多任务压力达到高峰
节点4: 恐慌 → 黑暗中只剩手电筒和声音
节点5: 决绝 → 明白"越过界限"的真正含义
节点6: 孤注一掷 → 完整的弹弓操作序列
```

**玩家角色弧线：** 迷茫的学习者 → 勉强胜任的操作者 → 多任务挣扎的幸存者 → 孤注一掷的逃亡者

## 3. Detailed Rules

### 3.1 驾驶舱布局

驾驶舱为第一人称固定视角，控件分散在舱内各处：

```
┌──────────────────────────────────────────────────┐
│              ┌── 主监视器（小地图）──┐             │
│              │  引力场+碎片+目的地标记  │             │
│              └────────────────────────┘             │
│                                                    │
│  ┌前方摄像头┐    ┌中央控件区┐    ┌后方摄像头┐       │
│  └──────────┘    │ ·点火按钮 │    └──────────┘       │
│                  │ ·导航旋钮 │                      │
│  ┌─────────┐    │ ·燃料阀门 │    ┌─────────┐       │
│  │左面板    │    │ ·推力推杆 │    │右面板    │       │
│  │·扫描调频 │    └──────────┘    │·O2补给阀 │       │
│  │·扫描开关 │                    │·冷却旋钮 │       │
│  │·断路器×4 │                    └─────────┘       │
│  └─────────┘                                       │
│         ┌── 系统面板 ──┐  ┌── 通讯面板 ──┐         │
│         │ 燃料│船体│氧气 │  │  叙事文字     │         │
│         │ 温度│断路器    │  │  操作提示     │         │
│         └──────────────┘  └──────────────┘         │
└──────────────────────────────────────────────────┘
```

### 3.2 控件系统

#### 控件分布

**中央裸露（始终可见可操作）：**

| 控件 | 类型 | 用途 |
|------|------|------|
| 点火按钮 (IgnitionBtn) | 按钮 | 触发推进/点火/弹弓最终点火 |
| 导航旋钮 (NavKnob) | 旋钮 (3档: NAV/LOCK/SLING) | 驾驶转向 + 锁定航道 + 弹弓模式 |
| 燃料阀门 (FuelValve) | 旋钮 (4档: OFF/LOW/MID/HIGH) | 控制飞船速度和燃料消耗 |
| 推力推杆 (ThrustLever) | 拉杆 (连续 0.0-1.0) | 弹弓时调节推力 |

**左侧面板内（点击打开）：**

| 控件 | 类型 | 用途 |
|------|------|------|
| 扫描调频旋钮 (ScanFreqKnob) | 旋钮 (连续) | 调整扫描频率/地图刷新 |
| 扫描开关 (ScanSwitch) | 开关 | 开始扫描/刷新地图 |
| 断路器1-4 (Breaker1-4) | 开关 | 各子系统断路器复位 |

**右侧面板内（点击打开）：**

| 控件 | 类型 | 用途 |
|------|------|------|
| O2 补给阀 (O2Valve) | 开关 | 氧气补给 |
| 冷却旋钮 (CoolingKnob) | 旋钮 (3档: OFF/LOW/HIGH) | 引擎冷却 |

**侧面板：** 左/右/底部各一块可开合面板，点击边缘/把手打开（旋转动画，0.5秒）。面板打开后内部控件可交互。所有面板和控件提供脚本调用接口（`open()`/`close()`/`activate()`/`set_value()` 等）。

#### 控件交互

| 类型 | 交互方式 |
|------|---------|
| 旋钮 (Knob) | 鼠标在旋钮上按下 → 水平拖拽旋转 → 松开吸附最近档位 |
| 按钮 (Button) | 鼠标点击 → 按下/弹起动画 |
| 开关 (Switch) | 鼠标点击 → 拨动切换 on/off |
| 拉杆 (Lever) | 鼠标拖拽上下 → 连续值变化 |
| 侧面板 | 点击边缘/把手 → 开合动画 |

所有控件共同提供：
- 鼠标悬停高亮（emission 颜色变化）
- 3D 动画反馈（Tween）
- 脚本接口：`set_enabled()`, `activate()`, `deactivate()`, `set_value()`, `get_value()`
- 信号：`interacted`, `value_changed`

#### 手电筒

- F 键或鼠标中键切换开/关
- SpotLight3D 挂在 PlayerCamera 子节点上
- 无电量限制
- 风暴期间（环境光关闭时）唯一光源
- 平时可选使用，帮助看清面板内部控件

### 3.3 小地图导航系统

#### 基本模型

- 主监视器显示当前节点的 2D 小地图
- 每个节点一张独立地图，7 张地图线性切换
- 飞船图标在小地图上实时移动
- 地图上有目的地标记，飞船飞入标记的判定半径即触发节点事件
- 线性流程：每张地图的目的地指向固定下游节点

#### 飞船物理（潜艇式）

```
操控：
  导航旋钮 → 转向（有最大转向速率，松手后缓慢回正）
  燃料阀门 → 油门（OFF/LOW/MID/HIGH）

物理参数（config 驱动）：
  max_turn_rate: 45°/秒      ← 慢转向，需提前规划
  turn_damping: 0.85         ← 松手后旋钮缓慢回正
  acceleration: 80 px/s²     ← 加速较慢
  max_speed_low: 60 px/s
  max_speed_mid: 120 px/s
  max_speed_high: 200 px/s
  drag: 0.02                 ← 水阻力式减速
  gravity_pull: 向"黑洞边"拉力，强度随位置变化
```

驾驶手感为潜艇式：速度慢、惯性大、转向迟缓。需要提前规划路线，反应太晚会撞上障碍。

#### 地图内容

**引力场（背景区域）：**
- 从"黑洞边"（地图底部）到"远离边"（地图顶部），引力逐渐减弱
- 颜色深浅表示强度：深紫/深蓝（强）→ 浅蓝/透明（弱）
- 效果：减速 + 向底部方向拉力
- 靠近底部的区域引力极强，飞船很难对抗

**碎片（离散障碍）：**
- 地图上散布碎片标记（小红色圆点/区域）
- 碰撞后果：轻碰 hull -2-3%，高速碰撞 hull -5-8%
- 碎片位置在"地图刷新"前可能不准确（偏移/缺失）

**目的地标记：**
- 近距离目的地：默认可见（绿色/黄色标记）
- 远距离目的地：需要扫描/刷新地图才显示
- 飞入目的地判定半径即触发到达

#### 地图数据更新（非实时，重度）

地图完全不自动更新。刷新方式：打开左侧面板 → 扫描调频旋钮对准频率 → 扫描开关 ON。

刷新后显示：
- 更新碎片位置（纠正偏移）
- 显示隐藏的远距离目的地
- 显示引力场准确强度分布

刷新后数据保持准确约 15-20 秒（config 配置），之后碎片缓慢漂移，引力场微调。地图刷新接口保留可供脚本调用，支持切换为实时模式（`set_realtime_update(bool)`）。

不刷新的后果：
- 导航基于旧数据 → 可能撞上看不见的碎片
- 远处目的地不可见 → 只能凭记忆或猜测

### 3.4 资源管理

| 指标 | 显示方式 | 耗尽后果 |
|------|---------|---------|
| **燃料** | 像素风进度条 | 无法驱动飞船，被引力吸入 |
| **船体** | 像素风进度条 | 解体（GAME OVER） |
| **氧气** | 数字倒计时 | 窒息（GAME OVER） |
| **引擎温度** | 温度条 + 指示灯 | 过热导致效率下降 + 断路器频率翻倍 |

资源消耗来源：
- 氧气：持续消耗（0.05%/秒）
- 燃料：驾驶消耗（根据阀门档位，HIGH > MID > LOW）、扫描消耗、O2补给消耗
- 船体：碎片碰撞、风暴撞击
- 引擎温度：HIGH档驾驶积累、断路器级联、自然散热

### 3.5 玩家操作

#### 持续驾驶循环

玩家通过导航旋钮和燃料阀门持续驾驶飞船在小地图上移动。这不是单次操作，而是持续的驾驶过程：

```
循环：
  1. 调整导航旋钮 → 转向（持续操作）
  2. 调整燃料阀门 → 控制速度
  3. 观察小地图 → 避开碎片和强引力区
  4. 需要时：扫描刷新地图数据
  5. 处理系统故障：断路器/O2/冷却
  6. 飞到目的地标记 → 自动触发节点事件
```

#### 扫描/地图刷新 — 3步

```
步骤1: 打开左侧面板
步骤2: 扫描调频旋钮 → 拖到正确频率
  - 小地图上显示信号强度条
  - 频率正确 → 信号满格
  - 频率偏差 → 信号弱或无
步骤3: 扫描开关 → ON
  - 地图刷新，更新碎片+显示隐藏目的地
  - 消耗燃料
  - 扫描期间飞船惯性滑行（无法驾驶）
  - 扫描完成开关自动弹回 OFF

注意：扫描时飞船仍在移动（惯性+引力拉力），
需要选择安全区域扫描，否则扫描期间可能漂进碎片
```

#### 推进（到达目的地后）

```
到达目的地标记 → 自动触发：
  - 过渡动画（transition_player）
  - 消耗资源（根据阀门档位系数）
  - 应用航道后果
  - 加载下一张地图
  - 阀门自动回到 OFF，导航旋钮回到 NAV
```

### 3.6 日常维持系统

#### 断路器

4 个断路器（左侧面板内），各控制一个子系统：
- SYS1: 前方摄像头
- SYS2: 后方摄像头
- SYS3: 小地图（主监视器）
- SYS4: 通讯面板

触发频率：
- 节点0-1: 不触发
- 节点2-3: ~30秒一次
- 节点5-6: ~15秒一次
- 引擎过热时: 频率翻倍

跳闸后果：
- 对应 SubViewport 冻结（UPDATE_ONCE）
- 小地图冻结时无法导航（最危险——失去视觉）
- 系统面板显示红色 "BREAKER X TRIPPED"

恢复操作：打开左侧面板 → 点击对应断路器 → 复位（0.5秒动画）

#### O2 补给

- 氧气低于 40% 时随机触发，comm_panel 提示"O2 补给系统待命"
- 操作：打开右侧面板 → 点击 O2 阀 → 3秒内恢复 10-15% → 自动关闭
- 忽略无额外惩罚，只是失去补充机会

#### 引擎冷却

- 引擎温度 >70% 时系统面板警告灯亮起
- >90% → 推进消耗 ×1.5 + 断路器频率翻倍
- 操作：打开右侧面板 → 冷却旋钮调 HIGH → 降温 -5%/秒
- 温度上升来源：HIGH档驾驶 +15%/次、断路器级联 +5%、自然散热 -1%/秒

### 3.7 节点流程（7 节点）

#### 节点 0 — 教学（~1分钟）

```
情境：飞船被黑洞引力捕获
────────────────────────────
- 简单开阔地图，少量碎片，一个明显目的地
- 无引力拉力，纯学习操控
- comm_panel 自由探索式教学：
  1. "导航系统已启动。查看主屏幕上的小地图。"
  2. "旋转导航旋钮来转向。调整燃料阀门控制速度。"
  3. "将飞船驶向绿色标记的目的地。"
  每步等待完成后显示下一条，错误时给出纠正提示
无失败可能
```

#### 节点 1 — 第一道分叉（~2分钟）

```
情境：小地图出现两个目的地
────────────────────────────
地图布局：
  两个目的地：左上（正确）和右上（错误）
  中间有碎片区隔开
  引力拉力轻微

信息差：
  近处目的地默认可见，远处需扫描
  扫描可揭示碎片密度和引力数据

正确路线：左目的地（碎片较少）
选错后果：船体损伤 -15%（碎片撞击），但不致死
```

#### 节点 2 — 残骸带（~2-3分钟）

```
情境：小地图上碎片密集
────────────────────────────
- 密集碎片区域，需要小心驾驶穿过
- 有残骸信号源（隐藏频率，需扫描调频发现）
- 单一目的地，但路途危险

可选操作：
  扫描残骸信号 → 消耗燃料+氧气 → 获得后续路线提示
  提示内容："航道 3，远离黑洞那条是死路……所有往外的都被拉回来……"

无路线分叉，但决定后续信息优势
```

#### 节点 3 — 三岔口（~3分钟）

```
情境：三个目的地，信息极不充分
────────────────────────────
地图布局：
  上方目的地：引力强度低，画面清晰（陷阱——看似安全）
  中间目的地：引力强度极高，画面扭曲严重（正确——弹弓出口）
  下方目的地：引力中等但碎片更多（错误——碎片密集）

只能扫描一条航线刷新地图

信息差设计：
  扫描上方：显示"碎片少，引力弱"——看似最安全
  扫描中间：显示"引力极强，稳定性未知"——信息不足
  扫描下方：显示"碎片密度高"——明显危险

如果之前扫描了节点2的残骸数据：
  地图上中间目的地旁出现一个小标记
  暗示"引力最强的方向是弹弓出口"

正确路线：中间目的地（引力最强 = 最大弹弓效应）
选上方后果：燃料 -20%（浅引力区无法获得弹弓速度）
选下方后果：船体损伤 -25%（碎片密集）
```

#### 节点 4 — 引力风暴（~3分钟）

```
情境：环境光关闭，纯黑暗 + 手电筒 + 音效
────────────────────────────
风暴开始：
  1. WorldEnvironment 环境光关闭
     整个 3D 世界变暗，只有自发光物体可见
     - 控件指示灯（微弱）
     - 吸积盘余光（远处）
     - 屏幕显示雪花/噪点
  2. 断路器全部跳闸 → 所有屏幕冻结
  3. 不是驾驶节点，而是纯操作+音效节点

操作序列：
  每轮：听到碎片接近声（音效）→ 3秒窗口
  → 玩家需按点火按钮或 Space 减速
  → 按对：轻微磨损（hull -1%, fuel -3%）
  → 没按：重创（hull -8%）
  → 3轮，窗口递减（1.5s → 1.1s → 0.7s）

手电筒在风暴中：
  必须照亮控制台才能看到/操作控件
  手电筒只能照亮一小块区域
  需要在"看控件"和"准备按Space"之间切换

风暴结束：环境光恢复 → 自动推进到节点5
```

#### 节点 5 — 最后的岔路（~2分钟）

```
情境：两个目的地，资源已不多了
────────────────────────────
地图布局：
  左目的地：指向"事件视界"——黑洞方向
  右目的地：指向外围——看似远离黑洞

强引力拉力：不操作会被吸向底部

信息暗示：
  右目的地方向可见大量碎片残骸——"远离"方向的船都被拉回来了

comm_panel 最后信号：
  "不要远离。要利用它。最深的引力就是最大的弹弓。"

正确路线：左目的地（冲向事件视界 = 利用最大引力弹弓）
选右目的地 → 被引力拉回 → BAD ENDING: 被吞噬
```

#### 节点 6 — 逃逸弹弓（~2-3分钟）

```
情境：以极近距离掠过事件视界
────────────────────────────
不是自由驾驶节点，而是固定5步操作序列：

步骤1: 燃料阀门 → HIGH（必须最大推力）
步骤2: 导航旋钮 → SLING 档（弹弓模式）
步骤3: 推力推杆 → 推到合适位置（0.6-0.7最佳）
  - <0.5: 推力不足
  - >0.8: 推力过大
步骤4: 按下点火按钮 → 弹弓启动
  - 所有屏幕剧烈扭曲 + 驾驶舱震动
  - HUD 进度条出现（8秒从左到右）
步骤5: 进度条到达最佳区域时 → 再次按下点火按钮

判定（推力值 + 时机综合）：
  时机<40% 或 推力<0.3 → CONSUMED（被吞噬）
  时机40%-60% 且 推力0.5-0.8 → ESCAPE（逃逸成功）
  时机>60% 或 推力>0.85 → DRIFT（漂流）
  未操作 → CONSUMED
```

### 3.8 结局

| 结局 | 触发条件 | 表现 |
|------|---------|------|
| **逃逸** | 节点5选左 + 节点6正确时机和推力 | 引力场图恢复正常。前方摄像头看到星光。系统日志："弹弓机动成功。已脱离引力捕获。" |
| **漂流** | 节点5选左 + 节点6过晚或推力过大 | 引力场图显示引力减弱但方向未知。系统日志："弹弓机动偏差。引擎燃料耗尽。漂流中。" |
| **被吞噬** | 节点5选右 / 节点6过早或未操作 | 画面逐渐被黑暗吞噬。前方摄像头最后看到事件视界越来越大，然后黑屏。 |

## 4. Formulas

### 4.1 飞船物理

```
// 驾驶物理（每帧）
ship_velocity += heading * acceleration * fuel_valve_factor * delta
ship_velocity *= (1.0 - drag)
ship_velocity += gravity_direction * gravity_strength_at_position * delta
ship_rotation += turn_input * max_turn_rate * delta
ship_rotation *= turn_damping

// 速度上限
max_speed = [0, 60, 120, 200][fuel_valve_position]  // OFF/LOW/MID/HIGH
ship_velocity = ship_velocity.limit_length(max_speed)

// 燃料消耗（驾驶中，每秒）
fuel_drain_per_second = [0, 0.05, 0.12, 0.25][fuel_valve_position]

// 引擎温度（每秒）
engine_temp_change = -1.0                          // 自然散热
if fuel_valve == HIGH:
    engine_temp_change += 15.0 * delta             // HIGH档积累
if engine_temp > 90:
    fuel_consumption_multiplier = 1.5              // 过热惩罚
if cooling_knob == LOW:
    engine_temp_change -= 2.0
elif cooling_knob == HIGH:
    engine_temp_change -= 5.0
```

### 4.2 碰撞

```
// 碎片碰撞
debris_collision_damage = base_collision_damage * (ship_speed / max_speed_mid)
base_collision_damage = 2.0    // 低速
high_speed_threshold = 0.7     // 速度超过 70% 上限
if speed_ratio > high_speed_threshold:
    debris_collision_damage *= 2.5  // 高速碰撞 -5-8%
```

### 4.3 引力场

```
// 引力强度（基于位置）
// 地图底部 y=0 为黑洞边，顶部 y=height 为远离边
gravity_ratio = 1.0 - (ship_y / map_height)
gravity_strength = gravity_base * pow(gravity_ratio, 1.5)

// 引力效果
gravity_pull_force = gravity_direction * gravity_strength
speed_penalty = 1.0 - gravity_ratio * 0.5  // 越靠近黑洞越慢
```

### 4.4 资源消耗

```
// 持续消耗
oxygen_drain_rate = 0.05       // %/秒
fuel_drain_driving = fuel_valve_factor  // 驾驶中持续消耗

// 一次性消耗
scan_fuel_cost = 8.0           // %
o2_supply_amount = 12.0        // %
o2_supply_duration = 3.0       // 秒
brake_fuel_cost = 3.0          // %

// 初始值
initial_fuel = 100.0
initial_hull = 100.0
initial_oxygen = 100.0
initial_engine_temp = 20.0     // %
```

### 4.5 断路器跳闸

```
// 跳闸概率（每秒）
breaker_trip_chance = base_trip_rate * gravity_factor * heat_factor
base_trip_rate = 0.02          // 节点2-3
gravity_factor = blackhole_scale / 2.0
heat_factor = 1.0
if engine_temp > 70:
    heat_factor = 2.0
if engine_temp > 90:
    heat_factor = 4.0

// 节点5-6 基础概率翻倍
if current_node >= 5:
    base_trip_rate = 0.04
```

### 4.6 扫描/地图刷新

```
// 信号强度
signal_strength = 1.0 - min(abs(knob_value - target_frequency) / frequency_range, 1.0)

// 扫描效果
if signal_strength > 0.7:
    scan_time = 3.0             // 快速刷新
    map_accuracy = 1.0          // 完全准确
elif signal_strength > 0.3:
    scan_time = 5.0             // 中速
    map_accuracy = 0.7          // 部分偏差
else:
    scan_failure = true         // 扫描失败

// 数据过期
data_freshness_duration = 15.0  // 秒，之后数据开始漂移
debris_drift_speed = 5.0        // px/s，碎片漂移速度
```

### 4.7 弹弓判定

```
// 进度条参数
slingshot_duration = 8.0
optimal_zone_start = 0.4
optimal_zone_end = 0.6
optimal_thrust_min = 0.5
optimal_thrust_max = 0.8

// 判定
if not fired:
    result = CONSUMED
elif ignition_time < optimal_zone_start or thrust < 0.3:
    result = CONSUMED
elif ignition_time > optimal_zone_end or thrust > 0.85:
    result = DRIFT
elif thrust >= optimal_thrust_min and thrust <= optimal_thrust_max:
    result = ESCAPE
else:
    result = DRIFT
```

## 5. Edge Cases

### 玩家不操作

- **节点 0：** comm_panel 每隔一段时间重复提示操作引导。
- **节点 1-5：** 氧气持续消耗。氧气耗尽 = GAME OVER。驾驶中不转向会被引力拉向黑洞。
- **节点 6：** 进度条自动走完，未点火 = CONSUMED 结局。

### 燃料耗尽

- 燃料阀门自动回到 OFF，飞船无法加速。
- 飞船被引力裹挟缓慢漂移（仍有惯性+引力拉力）。
- 仍可操作其他控件（断路器/O2等），但无法驾驶或扫描。
- 如果发生在节点 5 之前，大概率进入 CONSUMED 结局。

### 船体归零

- 直接 GAME OVER：系统日志"船体完整性丧失"。
- 可发生在任何碎片碰撞或风暴撞击累积后。

### 小地图断路器跳闸（SYS3）

- 主监视器冻结，玩家失去导航视觉。
- 必须打开左侧面板复位对应断路器才能恢复。
- 恢复前只能凭记忆驾驶（极其危险）。

### 扫描期间漂入碎片

- 扫描时飞船惯性滑行，无法驾驶。
- 如果扫描位置不安全，可能碰撞碎片。
- 扫描本身不会被打断，但碰撞会造成船体损伤。

### 所有断路器同时跳闸

- 所有屏幕冻结（摄像头+地图+通讯）。
- 只有系统面板可见（不在 SubViewport 内）。
- 需要逐个复位，手电筒帮助在黑暗中找到面板。

### 节点 5 选右目的地

- 飞船朝外围飞去，似乎远离黑洞。
- 引力逐渐减速，飞船被拉回。
- 几秒后进入 CONSUMED 结局。

### 引擎温度过高

- 温度 >90% 后效率下降 + 断路器频率翻倍。
- 如果不冷却，可能陷入"过热→断路器频跳→无法驾驶→碰撞→更多损伤"的恶性循环。

### 侧面板关闭时控件不可交互

- 面板关闭时内部控件碰撞体不可用。
- 必须先打开面板才能操作内部控件。
- 脚本可通过 `open()` 接口强制打开面板。
