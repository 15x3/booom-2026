# 事件视界 (Event Horizon)

**类型：** 第一人称驾驶舱导航 / 信息差决策  
**引擎：** Godot 4.6 (GL Compatibility) + Jolt Physics  
**美术风格：** Blockbench Low-Poly 驾驶舱 + 程序化引力场图 + 像素风仪表盘  
**目标时长：** 25-30 分钟  
**主题契合：** 视界限 — "有限的视野构建无限的悬念"  
**开发周期：** 3 周 / 2 人 / 每人每日 2 小时 (共 84 人时)

---

## 1. Overview

玩家驾驶一艘深空探测船被黑洞引力捕获，舷窗外只有扭曲的黑暗。所有对外的感知只能通过驾驶舱内的监视器和仪表盘——引力场图谱、前方摄像头、后方摄像头、系统状态面板。玩家需要在这些有限且被引力透镜扭曲的信息中，于引力航道分叉处做出导航决策，逐步找到逃逸弹弓点。

核心矛盾：扫描航道获取更多信息 = 消耗更多燃料和氧气 = 留给推进的资源更少。你必须在不充分的信息下做出"全有或全无"的决策。正确的逃逸路线不是远离黑洞，而是利用最深的引力弹弓效应——穿越视界限本身。

---

## 2. Player Fantasy

**核心幻想：** 你被密封在一个铁罐里，以引力弹弓的速度掠过地狱之门。你能依靠的只有四块屏幕和不完整的直觉。

**情感曲线：**

```
节点0: 恐慌 → "我被抓住了"的失控感
节点1: 谨慎 → 开始学习在信息不足中做选择
节点2: 沉重 → 看到前人失败的证据
节点3: 困惑 → 信息最不充分的时刻，必须赌
节点4: 恐惧 → 所有屏幕都在失效，只剩本能
节点5: 领悟 → 明白"越过界限"的真正含义
节点6: 决绝 → 冲向黑暗，在最后一刻点燃引擎
```

**玩家角色弧线：** 被动受害者 → 谨慎观察者 → 信息赌徒 → 孤注一掷的逃亡者

## 3. Detailed Rules

### 3.1 驾驶舱布局

驾驶舱为第一人称固定视角，玩家始终坐在驾驶座上。舱内布局：

```
┌──────────────────────────────────────────────┐
│                                              │
│   ┌──────────────────────────────────────┐   │
│   │                                      │   │
│   │        主监视器（引力场图）            │   │
│   │   显示引力航道/障碍/逃逸点方向         │   │
│   │                                      │   │
│   └──────────────────────────────────────┘   │
│                                              │
│  ┌──────────┐              ┌──────────┐      │
│  │ 前方摄像头 │              │ 后方摄像头 │      │
│  │ (前方实况) │   驾驶座    │ (身后实况) │      │
│  └──────────┘              └──────────┘      │
│                                              │
│         ┌──────────────────────┐             │
│         │   系统面板（仪表盘）   │             │
│         │  燃料│船体│氧气│警告  │             │
│         └──────────────────────┘             │
│                                              │
│    [扫描]  [推进(选择航道)]  [减速(消耗燃料)]   │
└──────────────────────────────────────────────┘
```

### 3.2 监视器系统

#### 主监视器 — 引力场图

- **默认视图：** 以飞船为中心的 2D 俯视引力场图
- **显示内容：** 引力航道（亮色流线）、障碍区（红色高亮）、已知逃逸点方向（黄色标记）
- **引力透镜效果：** 靠近黑洞方向的区域被扭曲/拉伸，信息不可靠
- **可切换模式：** 引力场图 / 前方实况 / 扫描结果
- **键盘 1-3 快速切换**

#### 前方摄像头

- 飞船行进方向的实时 3D 画面（SubViewport 渲染）
- 受引力透镜影响，画面边缘扭曲，靠近黑洞时扭曲加剧
- 可见：碎片场、其他船只残骸、引力异常闪光
- **叙事功能：** 飞越残骸时，看到前人失败的结果

#### 后方摄像头

- 飞船身后方向的 3D 画面（SubViewport 渲染）
- 显示已经过的航道如何在身后变化
- **信息价值：** 后方航道可能坍塌/关闭——告诉你回不去了

#### 系统面板

| 指标 | 显示方式 | 耗尽后果 |
|------|---------|---------|
| **燃料** | 像素风进度条 | 失去机动性，缓慢被吸入 |
| **船体** | 像素风进度条 | 解体（GAME OVER） |
| **氧气** | 数字倒计时 | 窒息（GAME OVER） |
| **警告** | 闪烁指示灯 | 提示当前威胁 |

### 3.3 玩家操作

| 操作 | 输入 | 效果 | 消耗 |
|------|------|------|------|
| **查看监视器** | 鼠标点击对应区域 | 放大该监视器画面 | 无 |
| **切换主监视器模式** | 键盘 1-3 | 切换引力场图/前方实况/扫描结果 | 无 |
| **扫描航道** | 点击扫描按钮 + 选择航道 | 揭示选中航道的部分属性 | 燃料 -8% + 时间 5 秒 |
| **推进（选择航道）** | 点击推进按钮 + 选择航道 | 飞船沿选定航道前进至下一节点 | 燃料 -5% + 氧气 -3% |
| **减速** | 点击减速按钮 | 在危险区域减缓速度，降低船体损伤 | 燃料 -3% |

### 3.4 引力航道系统

#### 航道属性

每个航道分叉处的可选航道具有以下隐藏属性：

| 属性 | 说明 | 扫描揭示程度 |
|------|------|-------------|
| **稳定性** | 航道是否可能坍塌 | 高 — 可明确显示 |
| **碎片密度** | 是否有残骸/碎片 | 中 — 近处准确，远处模糊 |
| **引力强度** | 对船体的压力 | 高 — 数值显示 |
| **逃逸概率** | 是否通向逃逸点 | 低 — 只显示模糊方向箭头 |

**扫描规则：** 每个分叉点只能扫描一条航道。扫描需要 5 秒（期间画面显示扫描进度条，引力场图上对应航道逐渐亮起）。扫描结果在主监视器上以颜色/数值标注。

#### 航道行进

选择航道后飞船自动沿航道前进，无需实时操控。行进过程中：

- 前方/后方摄像头显示实时画面
- 引力场图更新当前位置
- 碎片密集区域对船体造成持续损伤
- 引力强度高的区域画面扭曲加剧
- 到达下一个分叉节点时飞船自动减速停留

### 3.5 节点流程（7 节点，6 次选择）

#### 节点 0 — 坠入（教学）

```
情境：飞船被黑洞引力捕获
────────────────────────────
- 驾驶舱震动，红色警报灯闪烁
- 系统自动广播："引力捕获警报。计算逃逸路线中……仅有一条可用航道。"
- 引力场图上仅显示一条亮色航道
- 玩家操作：查看引力场图 → 点击推进 → 进入唯一航道
- 行进中：前方摄像头看到黑洞的吸积盘边缘，引力场图显示飞船正在深入

时长：约 2 分钟
无失败可能
教学内容：查看监视器、推进、理解引力场图
```

#### 节点 1 — 第一道分叉

```
情境：航道分叉为两条
────────────────────────────
引力场图显示：
  左航道：稳定性高，引力强度中等
  右航道：稳定性中等，引力强度低

前方摄像头补充信息：
  左航道方向隐约可见碎片带反光
  右航道方向画面相对清晰

玩家可扫描一条获取更详细数据

时长：约 3 分钟
正确路线：右航道（碎片比中等引力更危险）
选错后果：船体损伤 -15%（碎片撞击），但不致死
扫描提示：扫描左航道会显示"碎片密度：高"，引导玩家选右
```

#### 节点 2 — 残骸带

```
情境：航道穿过一片其他飞船的残骸区
────────────────────────────
- 前方摄像头：大量残骸碎片在引力场中漂浮
- 后方摄像头：能看到来路的残骸散布
- 引力场图：残骸区域以暗红色标注
- [叙事元素] 某个残骸的信号灯仍在闪烁——航行记录仪还在工作

玩家选择：
  A) 花时间+燃料扫描残骸记录仪（燃料 -5%，氧气 -5%，获得后续路线提示）
  B) 直接通过（节省资源，但后续没有额外信息）

残骸数据内容（如果扫描）：
  "……航道 3，选择了外围方向……引力太强，拉回来了……
   ……航道 5，有两条路，远离黑洞的那条是死路……所有往外的都被拉回来……"

时长：约 4 分钟
无路线选择，但决定后续信息优势
```

#### 节点 3 — 三岔口

```
情境：三条航道，信息极不充分
────────────────────────────
引力场图显示：
  上航道：引力强度低，画面清晰，显示"浅引力区"
  中航道：引力强度极高，主监视器画面严重扭曲，信息几乎不可读
  下航道：引力强度中等，但前方摄像头看到更多残骸

只能扫描一条航道

信息差设计：
  - 扫描上航道：显示"稳定性：高，碎片：低"——看似最安全
  - 扫描中航道：显示"引力强度：极高，稳定性：未知"——信息不足
  - 扫描下航道：显示"碎片密度：高"——明显危险

如果之前扫描了节点 2 的残骸数据：
  引力场图上中航道旁会出现一个小标记（残骸数据的提示）
  暗示"引力最强的方向是弹弓出口"

时长：约 4 分钟
正确路线：中航道（引力最强 = 离黑洞最近 = 最大弹弓效应的出口）
选上航道后果：进入"浅引力区"，看似安全但无法获得足够弹弓速度，
             需要额外消耗大量燃料加速（燃料 -20%）
选下航道后果：碎片密集区域，船体损伤 -25%
```

#### 节点 4 — 引力风暴

```
情境：航道进入引力剧烈波动区域
────────────────────────────
- 所有监视器画面不稳定：闪烁、扭曲、间歇性黑屏
- 引力场图数据不可靠（数值跳变）
- 系统面板不断报警（虚假警报 + 真实警报混杂）
- 玩家必须在监视器"闪亮"的间隙获取信息

操作序列（纯操作节点，无路线选择）：
  1. 前方摄像头闪亮 1 秒 → 看到前方有大块碎片
  2. 玩家点击减速 → 降低撞击损伤
  3. 画面黑屏 3 秒（只有声音：引擎声 + 引力低频震动）
  4. 画面恢复 → 引力场图显示前方即将稳定
  5. 重复 2-3 次，每次窗口更短

时长：约 3 分钟
无路线选择
操作失误后果：每次未及时减速 → 船体损伤 -8%
全部操作正确：船体损伤 -3%（最小磨损）
```

#### 节点 5 — 最后的岔路

```
情境：两条航道，资源已经不多了
────────────────────────────
引力场图显示：
  左航道：指向"事件视界"——黑洞本身的方向
  右航道：指向外围——看似在远离黑洞

后方摄像头关键画面：
  右航道方向可见大量残骸——所有选择"远离"方向的船只残骸都在那里
  它们被引力拉回来了

对讲机收到最后一段信号（来自某个残骸的自动重播）：
  "……不要远离。要利用它。最深的引力……就是最大的弹弓。
   所有往外跑的都被拉回来了……往里走的……信号断了……"

时长：约 3 分钟
正确路线：左航道（冲向事件视界 = 利用最大引力弹弓逃出）
选右航道后果：被引力拉回，最终被吞噬 → BAD ENDING
```

#### 节点 6 — 逃逸弹弓

```
情境：以极近距离掠过事件视界，利用引力弹弓效应弹射出
────────────────────────────
- 主监视器：引力场图剧烈扭曲，几乎全是黑洞
- 前方摄像头：事件视界占据整个画面——纯粹的黑暗
- 所有仪表报警
- 驾驶舱剧烈震动

最终操作——点火时机：
  一个进度条从左向右移动，代表飞船在弹弓轨道上的位置
  进度条上有一个"最佳点火区"（占总量约 20%）
  玩家需要在进度条经过最佳区域时点击"点火"

结果：
  过早点火 → 推力不够，被吸入 → ENDING: 被吞噬
  过晚点火 → 错过窗口，轨道偏移 → ENDING: 漂流
  正确时机 → 引力弹弓成功，弹射出引力范围 → ENDING: 逃逸
  未操作 → 默认被吸入 → ENDING: 被吞噬
```

### 3.6 结局

| 结局 | 触发条件 | 画面 |
|------|---------|------|
| **逃逸** | 节点 5 选左 + 节点 6 正确时机 | 引力场图恢复正常。前方摄像头看到星光。驾驶舱安静了。系统日志："弹弓机动成功。已脱离引力捕获。" |
| **漂流** | 节点 5 选左 + 节点 6 过晚点火 | 飞船飘入深空，引擎熄火。引力场图显示引力减弱但方向未知。系统日志："弹弓机动偏差。引擎燃料耗尽。漂流中。" |
| **被吞噬** | 节点 5 选右 / 节点 6 过早或未操作 | 画面逐渐被黑暗吞噬。前方摄像头最后看到的事件视界越来越大，然后黑屏。系统日志自动记录，没有人会读到。 |

## 4. Formulas

### 4.1 资源消耗

```
// 基础消耗（每秒）
fuel_drain_rate = 0.0           // 仅操作时消耗
oxygen_drain_rate = 0.05        // %/秒，持续消耗
hull_drain_rate = 0.0           // 仅受事件/碰撞时消耗

// 操作消耗
scan_fuel_cost = 8.0            // %
scan_time = 5.0                 // 秒
scan_oxygen_cost = scan_time * oxygen_drain_rate

thrust_fuel_cost = 5.0          // %
thrust_oxygen_cost = 3.0        // %

brake_fuel_cost = 3.0           // %
brake_hull_savings = 7.0        // 减少的船体损伤 %

// 初始值
initial_fuel = 100.0            // %
initial_hull = 100.0            // %
initial_oxygen = 100.0          // %
```

### 4.2 航道行进损伤

```
// 碎片区域行进损伤
fragment_damage = base_fragment_damage * (1 - brake_factor)
base_fragment_damage = 15.0     // % 默认
brake_factor = 0.5 if player_braked else 0.0

// 高引力区域画面扭曲程度
lens_distortion = clamp(gravity_strength / max_gravity, 0.0, 1.0)
// lens_distortion 0.0 = 无扭曲, 1.0 = 最大扭曲
```

### 4.3 扫描揭示

```
// 扫描一条航道后揭示的信息
scan_reveal = {
    stability: ACCURATE,         // 精确数值
    fragment_density: APPROXIMATE, // 近处准确，远处±30%误差
    gravity_strength: ACCURATE,   // 精确数值
    escape_probability: HINT      // 仅显示方向箭头，模糊
}
```

### 4.4 节点 6 点火时机

```
// 进度条参数
slingshot_duration = 8.0        // 秒
optimal_zone_start = 0.4        // 进度条 40% 位置
optimal_zone_end = 0.6          // 进度条 60% 位置
optimal_zone_width = optimal_zone_end - optimal_zone_start  // 20%

// 判定
if ignition_time >= optimal_zone_start and ignition_time <= optimal_zone_end:
    result = ESCAPE
elif ignition_time < optimal_zone_start:
    result = CONSUMED
elif ignition_time > optimal_zone_end:
    result = DRIFT
```

## 5. Edge Cases

### 玩家不操作

- **节点 0：** 系统每 10 秒重复提示"检测到可用航道，请推进"，无超时。
- **节点 1-5：** 氧气持续消耗。氧气耗尽 = GAME OVER。不做决策的最坏后果是窒息。
- **节点 6：** 进度条自动走完，未点击点火 = CONSUMED 结局。

### 燃料耗尽

- 无法执行扫描、推进、减速。
- 飞船被引力裹挟沿默认（最危险的）航道移动。
- 仍然可以通过监视器观察，但无法改变路线。
- 如果发生在节点 5 之前，进入 CONSUMED 结局。

### 船体归零

- 直接 GAME OVER 画面：飞船解体动画 + 系统日志"船体完整性丧失"。
- 可发生在任何导致船体损伤的选择之后。

### 所有监视器同时故障（节点 4 引力风暴）

- 节点 4 的监视器故障是脚本化的——每次黑屏 3 秒后恢复，不会永久失效。
- 玩家无法在黑屏期间操作，只能在"闪亮窗口"内操作。

### 扫描选择后立即推进（不等扫描完成）

- 扫描进度条被打断，不显示扫描结果。
- 消耗的燃料和氧气不退还。
- 玩家失去了信息但也没有获得——纯粹的浪费。

### 节点 5 选择右航道后的表现

- 飞船沿右航道前进，前方摄像头显示远离黑洞。
- 2-3 秒后，引力场图显示速度在下降。
- 4-5 秒后，后方摄像头显示黑洞在……变大？（引力正在把飞船拉回来）
- 6-7 秒后，前方摄像头画面开始扭曲——黑洞在所有方向都可见
- 8 秒后：黑屏 → CONSUMED 结局


**初始化顺序：** 驾驶舱场景 → 监视器渲染 → 引力场图 → 导航节点 → 资源管理 → 事件驱动

## 8. Acceptance Criteria

### 核心体验

- [ ] 完整的 7 节点流程可从节点 0 玩到结局，无崩溃
- [ ] 单次完整游玩时间在 20-35 分钟范围内
- [ ] 情感曲线可被感知：恐慌→谨慎→沉重→困惑→恐惧→领悟→决绝

### 监视器系统

- [ ] 主监视器显示引力场图（航道流线、障碍标注）
- [ ] 前方/后方摄像头显示 3D 空间实况（SubViewport 渲染）
- [ ] 所有监视器叠加 CRT 效果（扫描线 + 色差）
- [ ] 引力透镜效果随黑洞距离动态变化（边缘扭曲加剧）
- [ ] 节点 4 引力风暴中监视器出现脚本化黑屏/闪烁

### 导航系统

- [ ] 每个分叉节点显示 2-3 条可选航道
- [ ] 扫描操作消耗燃料并揭示航道属性
- [ ] 推进操作消耗燃料和氧气，飞船移动到下一节点
- [ ] 航道属性（稳定性/碎片/引力/逃逸概率）有扫描揭示程度差异

### 资源管理

- [ ] 燃料/船体/氧气三项资源实时显示在系统面板
- [ ] 氧气持续消耗，操作消耗燃料，错误选择损伤船体
- [ ] 任意资源归零触发对应结局（死亡/漂流/被吞噬）

### 节点流程

- [ ] 节点 0（教学）：仅一条航道，玩家学会基本操作
- [ ] 节点 1（第一分叉）：二选一，扫描揭示碎片密度差异
- [ ] 节点 2（残骸带）：可选扫描残骸获取后续线索
- [ ] 节点 3（三岔口）：三选一，信息最不充分的赌注时刻
- [ ] 节点 4（引力风暴）：纯操作，监视器间歇失效
- [ ] 节点 5（最后岔路）：二选一，叙事反转——向黑洞才是出路
- [ ] 节点 6（弹弓）：点火时机操作，决定最终结局

### 结局

- [ ] 三种结局各有独立画面和文本（逃逸/漂流/被吞噬）
- [ ] 节点 5 选右航道 → 被吞噬结局（不可逆）
- [ ] 节点 6 点火时机决定逃逸/漂流/被吞噬

### 音效

- [ ] 引擎持续低鸣作为背景音
- [ ] 黑洞引力有低频震动音效（随距离变化）
- [ ] 碎片撞击有金属碰撞声
- [ ] 系统警报有电子蜂鸣声
- [ ] 节点 5 对讲机信号有通讯滤波效果

### 美术

- [ ] 驾驶舱内部为 Blockbench Low-Poly 风格
- [ ] 系统面板为像素风 UI
- [ ] 引力场图视觉风格统一（深色背景+亮色流线）
- [ ] 黑洞视觉有存在感（吸积盘+引力透镜+黑暗球体）
- [ ] 碎片/残骸在摄像头画面中可见

### Jam 交付

- [ ] 游戏有标题画面和简单操作说明
- [ ] 可构建为独立可执行文件（Windows）
- [ ] 包内含所有必要资源，无需外部依赖
